# 🚀 Mini NPU Simulator

`Mini NPU Simulator`는 입력된 패턴과 필터 간의 **MAC(Multiply-Accumulate)** 연산을 수행하여, 패턴이 어떤 형태(`Cross` 또는 `X`)에 더 가까운지 판정하고 연산 성능을 측정하는 학습용 시뮬레이터입니다.

---

## 1. 주요 기능

- **MAC 연산 기반 판정**: 패턴과 필터의 원소별 곱의 합을 계산하여 유사도 측정
- **사용자 모드 (3x3)**: 직접 필터와 패턴을 입력하여 즉석에서 결과 확인
- **JSON 분석 모드**: `data.json`에 정의된 대량의 테스트 케이스 자동 분석 및 성능 측정
- **라벨 정규화**: 다양한 형태의 입력 라벨을 표준 라벨로 통일
- **성능 벤치마크**: 각 연산의 평균 실행 시간(ms)과 총 연산 횟수(N²) 측정

---

## 2. 핵심 로직 및 수치 기준

### 💡 MAC (Multiply-Accumulate) Score
패턴($P$)과 필터($F$)의 동일한 위치의 원소를 곱하여 모두 더한 값입니다. 점수가 높을수록 해당 필터와 패턴이 유사함을 의미합니다.
- **계산 방식**: `sum(float(p[i][j]) * float(f[i][j]))`
- **시간 복잡도**: $O(N^2)$ (행렬의 모든 원소를 한 번씩 순회하며 곱셈과 덧셈을 수행하기 때문)

### ⚖️ 부동소수점 오차와 EPS (1e-9)
MAC 연산은 소수점 계산을 포함하므로 `1e-9` 크기의 허용 오차(`EPS`)를 적용합니다.
- **선정 근거**: Python의 `math.isclose()` 기본 상대 오차값인 `1e-9`를 준용하여, 미세한 계산 오차로 인한 잘못된 판정을 방지합니다.
- **조정 방법**: 데이터의 수치 범위가 매우 크거나 정밀도가 더 중요하다면 이 값을 조정할 수 있습니다.

### 🔄 라벨 정규화 (Normalization)
입력 데이터의 다양성을 수용하기 위해 아래와 같이 라벨을 표준화합니다.

| 입력 라벨 예시 | 내부 표준 라벨 |
|:---|:---:|
| `+`, `cross`, `c`, `plus` | **cross** |
| `x`, `diag` | **x** |
| `undecided` | **undecided** |

## 3. 모드별 동점(Tie-break) 처리 규칙

두 필터의 점수 차이가 `EPS` 미만일 경우, 시스템은 아래와 같이 동작합니다.

| 구분 | 사용자 입력 모드 (3x3) | JSON 분석 모드 (data.json) |
|:---|:---|:---|
| **판정 결과** | `UNDECIDED` 출력 | `UNDECIDED` 출력 |
| **성능 측정** | 평균 시간 및 연산 횟수 미출력 | 성능 통계에는 포함하되 결과는 `FAIL` |
| **실패 사유** | "판정 불가(|A-B| < 1e-9)" | "동점(UNDECIDED) 처리 규칙에 따라 FAIL" |

## 4. `data.json` 구성 및 규칙
`python`으로 읽어오면 딕셔너리 형태와 각 필터 패턴 데이터는 리스트 형태로 받아옵니다
```python
'filters': {'size_5': {
                        'cross': [[...], [...], [...], [...], [...]], 
                        'x':[[...]....]... }
}....

'patterns': {'size_5_1': {
                            'input': [[...]....],
                            'expected': 'x'
                         },
}.....


```
### 4-1. 필터 키 네이밍 규칙
필터 키는 `filters`나 `mac_filters`로 저장해야 합니다
- `size` + `숫자` 형식으로 구분하여야 합니다

### 4-2. 행렬 데이터 인식
패턴 키는 `cases` 나 `patterns` 로 저장해야 합니다
- `matrix`, `data`, `input`, `pattern`

### 4-3. 데이터 크기
해당 코드는 N^2에서 동작 확인을 하고자 N x N 형태에서만 동작합니다

핵심은 **“각 라벨 점수를 모두 계산해서 가장 큰 라벨을 선택”**하는 방식입니다.

### 6-1) 라벨 정규화 수정

```python
def normalize(label):
    """라벨 정규화"""
    if label is None:
        return ""
    s = str(label).strip().lower()

    if s in ["+", "cross", "c", "plus"]:
        return "Cross"
    if s in ["x", "diag"]:
        return "X"
    if s in ["triangle", "tri", "t"]:
        return "Triangle"
    if s == "undecided":
        return "UNDECIDED"

    return s
```

### 6-3) 다중 분류용 판정 함수 추가

기존 `analyze_case()` 대신 아래처럼 쓰면 됩니다.

```python
def analyze_case_3label(c_id, c_data, filters):
    p = get_mat(c_data)
    if p is None:
        raise ValueError("패턴 행렬을 찾을 수 없습니다.")

    if not isinstance(c_data, dict):
        raise ValueError("케이스 형식이 dict가 아닙니다.")

    try:
        size = int(c_data.get("size", len(p)))
    except (TypeError, ValueError):
        raise ValueError("size 값이 올바르지 않습니다.")

    exp = normalize(c_data.get("expected") or c_data.get("label"))
    name = c_data.get("name", f"size_{size}_{c_id}")

    scores = {}
    times = {}

    # 각 라벨별 점수 계산
    for label in LABELS:
        f = find_filter(filters, size, label)
        if f is None:
            raise ValueError(f"size_{size}의 {label} 필터를 찾을 수 없습니다.")

        scores[label] = mac_score(p, f)
        times[label], ops = benchmark(p, f)

    # 최고 점수 찾기
    sorted_scores = sorted(scores.items(), key=lambda x: x[1], reverse=True)
    best_label, best_score = sorted_scores[0]

    # 동점 처리
    if len(sorted_scores) >= 2 and abs(sorted_scores[0][1] - sorted_scores[1][1]) < EPS:
        pred = "UNDECIDED"
    else:
        pred = best_label

    res_tag = "PASS" if pred == exp else "FAIL"

    return {
        "c_id": c_id,
        "name": name,
        "size": size,
        "expected": exp,
        "pred": pred,
        "res_tag": res_tag,
        "scores": scores,
        "time_ms": sum(times.values()) / len(times),   # 3개 평균 시간
        "ops": ops,
    }
```

## 7. 대규모 데이터 처리 최적화 전략

| 전략 | 핵심 아이디어 | 효과 |
|---|---|---|
| 1. 필터 미리 맵으로 만들기 | `find_filter()`를 매번 탐색하지 않고 `(size, label)`로 딕셔너리화 | 탐색 속도 향상 |
| 2. 중복 계산 제거 | 같은 행렬의 크기, 정규화, 점수를 여러 번 다시 계산하지 않기 | CPU 절약 |
| 3. 점수 계산 최소화 | `sorted()` 대신 최고값만 유지 | 불필요한 정렬 비용 제거 |
| 4. 메모리 절약 | 결과를 모두 쌓지 말고 처리 후 바로 저장/출력 | RAM 사용 감소 |
| 5. 출력 최소화 | 대량 데이터에서 매번 자세히 출력하지 않기 | I/O 병목 감소 |
| 6. 예외처리 최소 범위화 | 꼭 필요한 곳만 `try-except` 사용 | 불필요한 비용과 혼란 감소 |
| 7. 로컬 변수 사용 | 반복문 안에서 전역 접근 줄이기 | 미세하지만 누적 성능 향상 |
| 8. 조기 종료 | 이미 최적 판정이 확정되면 더 이상 계산하지 않기 | 평균 실행시간 감소 |

## 8. CPU vs NPU 특성 비교

본 시뮬레이터는 소프트웨어(CPU)로 동작하지만, 실제 NPU 하드웨어와의 차이점은 다음과 같습니다.

| 특성 | CPU (본 시뮬레이터) | 실제 NPU (가속기) |
|:---|:---|:---|
| **연산 방식** | 직렬 처리 (루프 기반) | 대규모 병렬 처리 (PE Array) |
| **주요 병목** | 복잡한 분기문, 연산 속도 | 데이터 이동(Memory Wall), 대역폭 |
| **장점** | 유연한 로직 변경 가능 | MAC 연산에 특화된 압도적 속도 |

## 9. 예외 처리 내역

| 함수/구간 | 발생 가능 예외·문제 | 처리 방식 | 효과 |
|---|---|---|---|
| `input()` 루프 / JSON 모드 | `EOFError` | `try-except EOFError`로 잡아서 종료 | 입력이 끝나도 프로그램이 갑자기 멈추지 않음 |
| `analyze_case()` / `analyze_case_3label()` | `c_data`가 `dict`가 아님 | `isinstance(c_data, dict)` 검사 후 `ValueError` 발생 | 잘못된 케이스 형식을 바로 확인 가능 |
| `analyze_case()` / `analyze_case_3label()` | 패턴 행렬이 없음 | `get_mat(c_data)` 결과가 `None`이면 `ValueError` 발생 | 행렬 누락을 명확히 알 수 있음 |
| `size` 추출 부분 | `int()` 변환 실패 (`TypeError`, `ValueError`) | `try-except (TypeError, ValueError)` | `size` 값이 비정상일 때 원인 파악 가능 |
| `find_filter()` 사용 부분 | 원하는 필터를 못 찾음 | `f is None`이면 `ValueError` 발생 | JSON에 필터가 빠졌는지 바로 확인 가능 |
| `normalize()` | `label`이 `None` | `None`이면 빈 문자열 반환 | 문자열 메서드 오류 방지 |
| 필터/데이터 탐색 | `None`과 빈 값 구분 필요 | `if x is None:` 방식 사용 | 빈 리스트/딕셔너리와 “없음”을 구분 가능 |
| 성능 집계/보조 처리 | 불필요하게 넓은 예외 처리 | `except (TypeError, ValueError)`처럼 구체화 | 디버깅이 쉬워짐 |

## 10. 진단 및 개선

### 10-1. 데이터/스키마 문제
- 입력받을 데이터의 순서나 배치를 확인합니다(data.json 라벨 정규화)

### 10-2. 로직 문제
- 작성한 코드의 순서 배치가 잘못된 경우 발생할 수 있습니다
- 데이터를 넣어보기 전 작은 값의 임시 데이터를 생성해 미리 검증합니다 ex) 3x3 임시 데이터를 만들어 넣어봅니다
### 10-3. 수치 비교 문제
- 허용오차를 설정합니다 해당 문제에서는 `1e-9` 크기의 허용 오차(`EPS`)를 적용했습니다

- **입력 오류**: 사용자 모드에서 행/열 개수가 맞지 않거나 숫자가 아닌 경우 에러 메시지와 함께 재입력을 요구합니다.
```bash
--- 입력 패턴 입력 ---
1행 (3개, 공백 구분): 1 0 1
2행 (3개, 공백 구분): 0 1 
입력 오류: 3개의 숫자를 입력해야 합니다.. 처음부터 다시 입력해주세요.
```

- **파일 오류**: `data.json`이 없거나 형식이 잘못된 경우 프로그램을 안전하게 종료합니다.
```bash
메뉴를 선택하세요: 2
파일 오류: [Errno 2] No such file or directory: 'data.json'
```
- **필터 미발견**: 특정 크기의 필터가 `filters` 섹션에 없을 경우 해당 케이스는 오류 로그를 남기고 건너뜁니다.
```bash
# [1] 필터 로드
✓ size_13 필터 로드 완료 (Cross, X)
✓ size_25 필터 로드 완료 (Cross, X)

# [2] 패턴 분석 (라벨 정규화 적용)
⚠ size_5_1 처리 중 오류: size_5 필터를 찾을 수 없습니다.
⚠ size_5_2 처리 중 오류: size_5 필터를 찾을 수 없습니다.
...
```
