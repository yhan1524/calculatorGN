# 🚀 Mini NPU Simulator

`Mini NPU Simulator`는 입력된 패턴과 필터 간의 **MAC(Multiply-Accumulate)** 연산을 수행하여, 패턴이 어떤 형태(`Cross` 또는 `X`)에 더 가까운지 판정하고 연산 성능을 측정하는 학습용 시뮬레이터입니다.

---

## 1. 주요 기능

- **MAC 연산 기반 판정**: 패턴과 필터의 원소별 곱의 합을 계산하여 유사도 측정
- **사용자 모드 (3x3)**: 직접 필터와 패턴을 입력하여 즉석에서 결과 확인
- **JSON 분석 모드**: `data.json`에 정의된 대량의 테스트 케이스 자동 분석 및 성능 측정
- **라벨 정규화**: 다양한 형태의 입력 라벨을 표준 라벨로 통일
- **성능 벤치마크**: 각 연산의 평균 실행 시간(ms)과 총 연산 횟수(N²) 측정

---

## 2. 핵심 로직 및 수치 기준

### 💡 MAC (Multiply-Accumulate) Score
패턴($P$)과 필터($F$)의 동일한 위치의 원소를 곱하여 모두 더한 값입니다. 점수가 높을수록 해당 필터와 패턴이 유사함을 의미합니다.
- **계산 방식**: `sum(float(p[i][j]) * float(f[i][j]))`
- **시간 복잡도**: $O(N^2)$ (행렬의 모든 원소를 한 번씩 순회하며 곱셈과 덧셈을 수행하기 때문)

### ⚖️ 부동소수점 오차와 EPS (1e-9)
MAC 연산은 소수점 계산을 포함하므로 `1e-9` 크기의 허용 오차(`EPS`)를 적용합니다.
- **선정 근거**: Python의 `math.isclose()` 기본 상대 오차값인 `1e-9`를 준용하여, 미세한 계산 오차로 인한 잘못된 판정을 방지합니다.
- **조정 방법**: 데이터의 수치 범위가 매우 크거나 정밀도가 더 중요하다면 이 값을 조정할 수 있습니다.

### 🔄 라벨 정규화 (Normalization)
입력 데이터의 다양성을 수용하기 위해 아래와 같이 라벨을 표준화합니다.

| 입력 라벨 예시 | 내부 표준 라벨 |
|:---|:---:|
| `+`, `cross`, `c`, `plus` | **cross** |
| `x`, `diag` | **x** |
| `undecided` | **undecided** |

## 3. 모드별 동점(Tie-break) 처리 규칙

두 필터의 점수 차이가 `EPS` 미만일 경우, 시스템은 아래와 같이 동작합니다.

| 구분 | 사용자 입력 모드 (3x3) | JSON 분석 모드 (data.json) |
|:---|:---|:---|
| **판정 결과** | `UNDECIDED` 출력 | `UNDECIDED` 출력 |
| **성능 측정** | 평균 시간 및 연산 횟수 미출력 | 성능 통계에는 포함하되 결과는 `FAIL` |
| **실패 사유** | "판정 불가(|A-B| < 1e-9)" | "동점(UNDECIDED) 처리 규칙에 따라 FAIL" |

## 4. `data.json` 구성 및 규칙

### 4-1. 필터 키 네이밍 규칙
필터 데이터는 반드시 **`size_N`** 형식을 따라야 프로그램이 자동으로 크기를 인식합니다.
- 예: `"size_5"`, `"size_13"`, `"size_25"`

### 4-2. 행렬 데이터 인식
패턴 데이터에서 행렬을 추출할 때 아래 키들을 순차적으로 탐색합니다.
- `matrix`, `data`, `input`, `pattern`

## 5. 결과 리포트

### 5-1. 사용자 입력
1) A와 패턴이 동일
```bash

 - 필터 A 점수: 5.0000
 - 필터 B 점수: 1.0000
 - 평균 연산 시간: 0.001915 ms
 - 총 연산 횟수: 9 (N^2)
 - 판정: A
==================================================
```
2) B와 패턴이 동일
```bash
==================================================
 - 필터 A 점수: 1.0000
 - 필터 B 점수: 5.0000
 - 평균 연산 시간: 0.002010 ms
 - 총 연산 횟수: 9 (N^2)
 - 판정: B
==================================================
```
3) A,B의 값이 같은 경우
```bash
==================================================
 - 필터 A 점수: 5.0000
 - 필터 B 점수: 5.0000
 - 판정: 판정 불가(|A-B| < 1e-9)
==================================================
```
> 미션 예시에서 동점시 시간과 횟수를 출력하지 않아 해당 프로그램에서도 출력안하도록 함

## 6. 확장 및 최적화 가이드

### 6-1. 새 라벨 추가 절차
새로운 패턴(예: `Circle`)을 추가하려면 다음 단계를 따르세요.
1. `normalize()` 함수에 새 라벨 매핑 추가 (예: `if s == "o": return "circle"`)
2. `data.json`의 `filters`에 해당 크기의 `circle` 필터 행렬 추가
3. `analyze_logic()` 또는 `run_json_mode()`에서 비교 대상 필터에 `circle` 로직 반영

### 6-2. 대규모 데이터 처리 최적화 전략
데이터 크기($N$)나 케이스 수($M$)가 늘어날 경우 아래 전략을 권장합니다.
- **블록화(Blocking)**: 행렬을 작은 블록 단위로 나누어 CPU 캐시 효율 극대화
- **병렬화**: `multiprocessing`을 이용해 여러 패턴을 동시에 연산
- **벡터화**: 순수 Python 루프 대신 NumPy와 같은 라이브러리를 사용하여 SIMD 연산 활용

## 7. CPU vs NPU 특성 비교

본 시뮬레이터는 소프트웨어(CPU)로 동작하지만, 실제 NPU 하드웨어와의 차이점은 다음과 같습니다.

| 특성 | CPU (본 시뮬레이터) | 실제 NPU (가속기) |
|:---|:---|:---|
| **연산 방식** | 직렬 처리 (루프 기반) | 대규모 병렬 처리 (PE Array) |
| **주요 병목** | 복잡한 분기문, 연산 속도 | 데이터 이동(Memory Wall), 대역폭 |
| **장점** | 유연한 로직 변경 가능 | MAC 연산에 특화된 압도적 속도 |

## 8. 예외 처리 안내
- **입력 오류**: 사용자 모드에서 행/열 개수가 맞지 않거나 숫자가 아닌 경우 에러 메시지와 함께 재입력을 요구합니다.
```bash
--- 입력 패턴 입력 ---
1행 (3개, 공백 구분): 1 0 1
2행 (3개, 공백 구분): 0 1 
입력 오류: 3개의 숫자를 입력해야 합니다.. 처음부터 다시 입력해주세요.
```

- **파일 오류**: `data.json`이 없거나 형식이 잘못된 경우 프로그램을 안전하게 종료합니다.
- **필터 미발견**: 특정 크기의 필터가 `filters` 섹션에 없을 경우 해당 케이스는 오류 로그를 남기고 건너뜁니다.
